# 03 — Database Design

## 1. Principles

- PostgreSQL is the source of truth.
- Use UUID primary keys for major entities.
- Store timestamps in UTC (`timestamptz`).
- Add foreign keys and check constraints where practical.
- Index common list/filter paths.
- Use migrations for all schema changes.
- Never store plaintext passwords, provider tokens, or application secrets.
- Define ownership/authorization relationships explicitly.

This document describes the initial logical schema, not a final migration. Column types and constraints should be reviewed during implementation.

## 2. Core entities

| Table | Purpose |
|---|---|
| `users` | User accounts and password hashes |
| `sessions` | Browser sessions (hashed session tokens) |
| `enrollment_tokens` | Short-lived, single-use Agent enrollment tokens |
| `projects` | Project metadata and owner |
| `project_members` | Project membership and role |
| `git_connections` | Provider and encrypted credential reference |
| `registry_connections` | Container registry host, username, and encrypted password |
| `applications` | Repository/build configuration and image destination |
| `environments` | Target environment and deployment settings |
| `servers` | Registered machine metadata, owned by a project |
| `agents` | Agent identity, version, last heartbeat, revocation |
| `server_containers` | Latest container snapshot reported by a server's Agent |
| `pipelines` | Pipeline configuration/version |
| `jobs` | Queue state, type, payload, lease, retry count |
| `job_attempts` | Individual execution attempts |
| `job_log_chunks` | Ordered logs/events, subject to retention |
| `releases` | Image digest, commit, environment, result |
| `project_secrets` | Encrypted secret values and metadata |
| `webhook_events` | Provider delivery IDs for deduplication |
| `audit_logs` | Important security and operational actions |
| `setup_claim` | At most one row: taken by the first account registered from the web |


## 4. Suggested important columns

### `users`

- `id UUID PRIMARY KEY`
- `email TEXT UNIQUE NOT NULL`
- `password_hash TEXT NOT NULL`
- `created_at TIMESTAMPTZ NOT NULL`
- `updated_at TIMESTAMPTZ NOT NULL`

### `setup_claim`

- `singleton BOOLEAN PRIMARY KEY DEFAULT true CHECK (singleton)`
- `claimed_at TIMESTAMPTZ NOT NULL DEFAULT now()`

The first-account page inserts its row and the user in one statement, and only when `users` is empty. Two registrations at the same moment race for the single row, so only one wins. An installation that already has users never offers the page, whether or not this row exists.

### `sessions`

- `id UUID PRIMARY KEY`
- `user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE`
- `token_hash BYTEA NOT NULL UNIQUE`
- `created_at TIMESTAMPTZ NOT NULL`
- `last_seen_at TIMESTAMPTZ NOT NULL`
- `expires_at TIMESTAMPTZ NOT NULL`

The browser cookie holds a random 32-byte token; only its SHA-256 hash is stored. Logout deletes the row. Index `expires_at` for cleanup and `user_id` for "sign out everywhere".

### Token hashing

Session tokens, enrollment tokens, and Agent credentials are high-entropy random values generated by the Control Plane, so they are stored as SHA-256 hashes and compared in constant time. Passwords are low-entropy and use argon2id instead.

### `projects`

- `id UUID PRIMARY KEY`
- `name TEXT NOT NULL`
- `slug TEXT NOT NULL`
- `created_by UUID REFERENCES users(id)`
- `created_at`, `updated_at`

Use a uniqueness rule for project slugs within the relevant ownership scope.

### `project_members`

- `project_id UUID REFERENCES projects(id)`
- `user_id UUID REFERENCES users(id)`
- `role TEXT NOT NULL`
- Composite primary key `(project_id, user_id)`

Allowed roles should be constrained to the roles defined in the authorization design.

### `applications`

- `id UUID PRIMARY KEY`
- `project_id UUID NOT NULL REFERENCES projects(id)`
- `name TEXT NOT NULL`
- `git_connection_id UUID REFERENCES git_connections(id)`
- `repository_owner TEXT`
- `repository_name TEXT`
- `default_branch TEXT`
- `dockerfile_path TEXT`
- `build_context TEXT`
- `registry_connection_id UUID REFERENCES registry_connections(id) ON DELETE RESTRICT`
- `image_repository TEXT` — image path without host or tag, e.g. `acme/shop-api`; set together with the registry
- `created_at`, `updated_at`

Avoid storing provider access tokens directly on the application row.

### `registry_connections`

- `id UUID PRIMARY KEY`
- `project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE`
- `name TEXT NOT NULL`, unique per project
- `host TEXT NOT NULL` — e.g. `ghcr.io`, `registry.example.com:5000`
- `username TEXT NOT NULL`
- `password_ciphertext BYTEA NOT NULL`, `password_key_id TEXT NOT NULL` — AES-GCM, bound to the row ID
- `created_by`, `created_at`

Credentials are not checked when stored; the Runner's first push reports a bad password as a failed build.

### `environments`

- `id UUID PRIMARY KEY`
- `application_id UUID NOT NULL REFERENCES applications(id)`
- `name TEXT NOT NULL`
- `server_id UUID REFERENCES servers(id)`
- `auto_deploy BOOLEAN NOT NULL DEFAULT false`
- `config JSONB NOT NULL` — the validated service configuration ([15](15-deployments.md)); there is no user-supplied Compose file
- `published_port` and `server_id` back a unique index so two environments cannot claim the same host port
- `created_at`, `updated_at`

Use a unique constraint for environment name within an application. The server must belong to the application's project.

### `servers`

- `id UUID PRIMARY KEY`
- `project_id UUID NOT NULL REFERENCES projects(id) ON DELETE RESTRICT`
- `name TEXT NOT NULL`
- `last_seen_at TIMESTAMPTZ`
- `agent_version TEXT`
- `created_at`, `updated_at`

Online/offline status is computed from `last_seen_at` and the heartbeat timeout rather than stored, so it cannot go stale. A project cannot be deleted while it still has servers.

A server belongs to exactly one project. Authorization for a server, its containers, and its Agent jobs is resolved through `servers.project_id` and `project_members`. Index `project_id` for project-scoped listing and use a unique constraint for server name within a project.

Avoid treating client-reported CPU/memory values as trusted security data.

### `agents`

- `id UUID PRIMARY KEY`
- `server_id UUID NOT NULL UNIQUE REFERENCES servers(id) ON DELETE CASCADE`
- `credential_hash BYTEA NOT NULL UNIQUE`
- `created_at`

One Agent identity per server. Removing a server deletes its Agent row, which revokes the credential immediately. Credential rotation (Phase 5) replaces `credential_hash` in place.

Store credentials so they can be validated or rotated without exposing their raw values in ordinary database reads.

### `enrollment_tokens`

- `id UUID PRIMARY KEY`
- `project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE`
- `server_name TEXT NOT NULL` (name given to the server created on enrollment)
- `token_hash BYTEA NOT NULL UNIQUE`
- `created_by UUID REFERENCES users(id)`
- `created_at TIMESTAMPTZ NOT NULL`
- `expires_at TIMESTAMPTZ NOT NULL`
- `used_at TIMESTAMPTZ`
- `server_id UUID REFERENCES servers(id)` (set when used)

A token is valid only when `used_at IS NULL` and `expires_at > now()`. Mark it used in the same transaction that creates the server and Agent, using a conditional `UPDATE … WHERE used_at IS NULL` so two concurrent enrollments cannot both succeed.

### `server_containers`

Holds the latest container state reported by the Agent. It is a cache for the dashboard, not a history table.

- `server_id UUID NOT NULL REFERENCES servers(id)`
- `container_id TEXT NOT NULL` (Docker container ID)
- `name TEXT NOT NULL`
- `image TEXT NOT NULL`
- `state TEXT NOT NULL` (e.g. `running`, `exited`, `restarting`)
- `status_text TEXT` (Docker's human-readable status)
- `labels JSONB`
- `observed_at TIMESTAMPTZ NOT NULL` (when the Agent observed this state)
- `received_at TIMESTAMPTZ NOT NULL` (when the Control Plane stored it)
- Composite primary key `(server_id, container_id)`

Apply each snapshot in one transaction: lock the server row, delete its stored containers, and bulk-insert the reported ones. `servers.containers_observed_at` records the time of the last applied snapshot (even an empty one); a snapshot whose `observed_at` is not newer is ignored, so a delayed request cannot overwrite newer state.

`observed_at` is Agent-reported. The Control Plane should clamp values that are ahead of `received_at` beyond a small skew tolerance. The UI uses `observed_at` to show data age and marks the list stale when it exceeds a configurable threshold.

### `jobs`

- `id UUID PRIMARY KEY`
- `project_id UUID REFERENCES projects(id)`
- `application_id UUID REFERENCES applications(id)`
- `environment_id UUID REFERENCES environments(id)`
- `type TEXT NOT NULL` (e.g. `container_action`, `fetch_logs`, `build`, `deploy_image`)
- `worker_kind TEXT NOT NULL` (`agent` or `runner`)
- `target_server_id UUID REFERENCES servers(id)`
- `status TEXT NOT NULL`
- `payload JSONB NOT NULL`
- `attempt_count INTEGER NOT NULL DEFAULT 0`
- `max_attempts INTEGER NOT NULL`
- `lease_owner TEXT`
- `lease_expires_at TIMESTAMPTZ`
- `idempotency_key TEXT`
- `created_at`, `started_at`, `finished_at`

Constraints:
- Check `worker_kind IN ('agent', 'runner')` and valid `status` values.
- `worker_kind = 'agent'` requires `target_server_id IS NOT NULL`.
- `worker_kind = 'runner'` requires `target_server_id IS NULL` in MVP (Runner targeting can be added later).

Indexes:
- Agent claim path: partial index on `(target_server_id, created_at) WHERE status = 'queued' AND worker_kind = 'agent'`.
- Runner claim path: partial index on `(created_at) WHERE status = 'queued' AND worker_kind = 'runner'`.
- Lease recovery: partial index on `(lease_expires_at) WHERE status = 'running'`.
- Project/job history: `(project_id, created_at DESC)`.

### `job_attempts`

Record each attempt separately so retries do not erase prior failures:

- `id UUID PRIMARY KEY`
- `job_id UUID NOT NULL REFERENCES jobs(id)`
- `attempt_number INTEGER NOT NULL`
- `worker_id TEXT`
- `status TEXT NOT NULL`
- `started_at`, `finished_at`
- `error_code TEXT`
- `error_summary TEXT`

### `job_log_chunks`

- `id BIGINT GENERATED ... PRIMARY KEY`
- `job_id UUID NOT NULL REFERENCES jobs(id)`
- `attempt_number INTEGER NOT NULL`
- `sequence_number BIGINT NOT NULL`
- `stream TEXT NOT NULL`
- `content TEXT NOT NULL`
- `created_at TIMESTAMPTZ NOT NULL`

Ensure ordering and duplicate handling. Define retention/cleanup; logs can grow quickly.

### `deployments`

One attempt to put an image digest into an environment; every attempt is kept ([15](15-deployments.md)).

- `id UUID PRIMARY KEY`
- `environment_id UUID NOT NULL REFERENCES environments(id) ON DELETE CASCADE`
- `job_id UUID UNIQUE REFERENCES jobs(id) ON DELETE SET NULL` — the `deploy_image` job
- `source_build_job_id UUID`, `source_release_id UUID` — a succeeded build, or an earlier release when rolling back
- `commit_sha TEXT NOT NULL`
- `image_ref TEXT NOT NULL` — must end in `@sha256:<64 hex>`; a mutable tag is never deployed
- `config JSONB NOT NULL` — the service configuration this deployment applies
- `status` (`queued`, `running`, `succeeded`, `failed`, `cancelled`), `stage` (`pull`, `start`, `health_check`), `error_code`, `error_message`
- `created_by`, `created_at`, `started_at`, `finished_at`

### `releases`

A deployment that passed its health check. Immutable; a failed deployment is never a release. A rollback restores the release's image and `config` snapshot.

- `id UUID PRIMARY KEY`
- `application_id UUID NOT NULL REFERENCES applications(id) ON DELETE CASCADE`
- `environment_id UUID NOT NULL REFERENCES environments(id) ON DELETE CASCADE`
- `deployment_id UUID NOT NULL UNIQUE REFERENCES deployments(id) ON DELETE CASCADE`
- `commit_sha TEXT NOT NULL`
- `image_ref TEXT NOT NULL` — `registry/repo@sha256:…`
- `config JSONB NOT NULL` — snapshot
- `created_at TIMESTAMPTZ NOT NULL`

The current release of an environment is its newest row. Rollback targets a previously recorded immutable digest.

### `webhook_events`

- `id UUID PRIMARY KEY`
- `provider TEXT NOT NULL`
- `delivery_id TEXT NOT NULL`
- `event_type TEXT NOT NULL`
- `received_at TIMESTAMPTZ NOT NULL`
- `processed_at TIMESTAMPTZ`
- `result TEXT`

Use a unique constraint on `(provider, delivery_id)` to prevent duplicate processing.

### `project_secrets`

- `id UUID PRIMARY KEY`
- `project_id UUID NOT NULL REFERENCES projects(id)`
- `name TEXT NOT NULL`
- `ciphertext BYTEA NOT NULL`
- `key_version TEXT NOT NULL`
- `created_at`, `updated_at`

The encryption key must be provided from outside the database. Avoid returning decrypted values from list endpoints.

### `audit_logs`

An append-only record of who did what. Nothing updates a row; only the retention job removes them.

- `id UUID PRIMARY KEY`
- `project_id UUID` — **no foreign key**, so deleting a project does not erase the record of who deleted it; NULL for installation-level events
- `actor_user_id UUID REFERENCES users(id) ON DELETE SET NULL`
- `actor TEXT NOT NULL` — the actor as text so the record outlives the user: an email address, or `agent`, `runner`, `system`
- `action TEXT NOT NULL` — `<noun>.<verb>`, such as `secret.set`
- `target_type TEXT NOT NULL`, `target_id TEXT`, `target_name TEXT`
- `metadata JSONB NOT NULL` — non-sensitive details only; values under keys that look like credentials (`secret`, `password`, `token`, `credential`, `key`, `value`) are replaced with `[redacted]` before they are stored
- `request_id TEXT` — ties the event to the request that caused it
- `created_at TIMESTAMPTZ NOT NULL`

Events are written after the action they describe has succeeded. A failure to write is logged at error level and does not fail the action: the action has already happened.

## 5. Queue transaction requirements

Job claiming must be atomic. Use a transaction and a PostgreSQL pattern such as `FOR UPDATE SKIP LOCKED` so concurrent workers do not claim the same queued row at the same time. Claiming should set status, owner, lease expiry, and attempt information consistently.

The claim query must filter by the caller's identity, never by a value the caller supplies:
- Agent: `worker_kind = 'agent' AND target_server_id = <server bound to the authenticated Agent>`.
- Runner: `worker_kind = 'runner'`.

To support long-poll claims without busy queries, inserting a queued job may issue `NOTIFY` on a channel (for example keyed by `target_server_id`). Each API process holds one `LISTEN` connection and wakes waiting claim requests in memory. A notification is only a hint: the claim still runs the `SKIP LOCKED` query, and waiting requests also recheck on a timer in case a notification is missed. Waiting claim requests must not hold a pooled database connection while idle.

## 6. Retention

A background pass removes data that has outlived its use. It runs about a minute after the Control Plane starts and then every 6 hours, deletes in batches of 2000 so a backlog never holds a long lock, and logs how much it removed. Every step is a delete by age, so running it twice, or from two processes, is harmless.

| Data | Kept for (default) | Setting | What is removed |
|---|---|---|---|
| Job log lines | 30 days after the job finished | `FORGEDECK_RETENTION_JOB_LOGS_DAYS` | The lines only. The job stays, marked `logs_expired`, and the dashboard says the output was removed. |
| Finished jobs | 180 days | `FORGEDECK_RETENTION_JOBS_DAYS` | The job, its attempts and its logs. Jobs that are queued or running are never removed. |
| Webhook deliveries | 30 days | `FORGEDECK_RETENTION_WEBHOOKS_DAYS` | Delivery records. Providers redeliver within days, so this window still deduplicates. |
| Audit events | 365 days | `FORGEDECK_RETENTION_AUDIT_DAYS` | Audit rows. |
| Sessions | 1 day after they expire | not configurable | Expired sessions. |
| Enrollment tokens | 7 days after use or expiry | not configurable | Used and expired tokens. |

`0` keeps a kind forever; negative or non-numeric values, and keeping job logs longer than the jobs themselves, are rejected at start-up.

**Never removed automatically:** releases and deployments. A release is what a rollback restores, and the deployment history is small. Deleting a *job* does not touch them: deployments only lose the link to a job that no longer exists (and keep their own status and error), and releases do not depend on jobs at all. The one consequence is that a build older than the job retention can no longer be picked for a new deployment from its job; deploying a release again (rollback) is unaffected.

Not stored, so nothing to remove: container snapshots are replaced on every report, and server metrics keep only the latest values.

## 7. Open decisions

- Whether projects are owned by a user or by an explicit organization table. (Servers belong to projects in MVP; moving them to organization scope later requires a migration.)
- Exact schema for encrypted Git provider credentials.
- Whether logs begin in PostgreSQL or use an append-only file/object storage backend.
- How environment variables are versioned and associated with releases. *(Resolved for plain variables: each release stores a configuration snapshot, see [15](15-deployments.md). Secrets follow in Phase 5.)*
- Whether server metrics are stored historically or only current values are retained.
